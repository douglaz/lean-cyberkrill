# Amount parser fixtures

`cli.json` contains 124 synthetic inputs and exact decimal expectations. Integers
are strings so no JSON reader can round them through binary floating point.
`delta` names an intentional rejection; `upstreamMsat` lists the four accepted
inputs whose exact value differs from the reference's floating-point result or
u64 saturation. No expected value comes from the Lean implementation.

`cyberkrill-amounts.json` is captured output on our own synthetic inputs from
[douglaz/cyberkrill](https://github.com/douglaz/cyberkrill/tree/27cad1faba86260b06665a89f0af5134d23525c2),
commit `27cad1faba86260b06665a89f0af5134d23525c2`,
`cyberkrill-core/src/bitcoin_rpc.rs`, `AmountInput::from_str` and
`AmountInput::as_millisats`. Upstream is MIT OR Apache-2.0, taken under MIT.
Only output is captured; no reference source code is copied here.

From the repository root:

```bash
python3 packages/bitcoin/capture-cyberkrill.py
```

The script retains its fresh clone and private cache in a temporary directory, adds one
pure parser test, fetches with that revision's `nix develop`, then builds and runs
only that test offline under `unshare -rn` with a throwaway HOME. The test never
constructs a client or opens a connection. Its stdout/stderr are captured
separately in `.lake/capture-checks/`. The committed JSON is the extracted test
output, with name/input columns checked against all 124 source rows.

## RIPEMD-160 fixtures

`ripemd160.json` holds nine messages as ASCII base strings and repeat counts,
with 20-byte digests generated by `generate-ripemd160-vectors.py` using
`openssl dgst -ripemd160 -binary`. The fixture records the OpenSSL version and
the message-selection source URL. No expected digest is copied from that page.
The 80-byte and million-byte messages expand at test time. Regenerate from the
repository root with:

```bash
nix develop -c python3 -I packages/bitcoin/generate-ripemd160-vectors.py
git diff --exit-code -- packages/bitcoin/test-data/ripemd160.json
```

`ripemd160-mutations.json` records each mutation's property, source, foreground
command, exit and observed first failure. `check-ripemd160-mutations.py` keeps
separate stdout/stderr under `.lake/ripemd160-mutation-checks`, restores source
bytes in `finally`, and finishes with a successful full `lake test`.
The existing `psbt-mutations.json` skip/swap cases for types 10 and 12 now test
the exported real hashes with independently constructed record digests.

## BIP39 English fixtures

`bip39-english-vectors.json` extracts only entropy and mnemonic from the 24
English rows of [python-mnemonic vectors.json](https://github.com/trezor/python-mnemonic/blob/b57a5ad77a981e743f4167ab2f7927a55c1e82a8/vectors.json),
commit `b57a5ad77a981e743f4167ab2f7927a55c1e82a8`. Source SHA-256:
`fa3b937b7cff9c9b8ecd3aa011faeb8d6dd67993174b72326e83f4de8fdb30f8`.
The MIT attribution and verbatim notice are in `LICENSE-python-mnemonic`;
the sidecar records the extraction and the dropped seed, xprv and other-language
data. The extract has eight rows each of 12, 18 and 24 words.

From the root, with `TMP_ROOT` set to a private temporary workspace:

```bash
TMPDIR="${TMP_ROOT:?}" python3 -I packages/bitcoin/generate-bip39-vectors.py
git diff --exit-code -- packages/bitcoin/test-data/bip39-english-vectors.json
```

The script pins the source digest and row counts, permits exactly the two
retained fields, and checks that none of the 24 English seed or xprv values
appears in the output. No complete upstream vector file is kept in the tree.
All 15/21-word, invalid-checksum, unknown-word, invalid-count and invalid-length
cases are derived at test time from these published rows. No derived mnemonic
is committed.

The wordlist is the separate byte-identical `Bitcoin/bip39-english.txt`, with
its own provenance and MIT notice. `bip39-mutations.json` records nine
production mutations: five caught during theorem builds and four by tests.
`check-bip39-mutations.py` checks exact replacement counts and pins each
proof-caught mutation to one theorem whose statement the edit falsifies.
It records the first diagnostic inside that theorem's original declaration
range and fails if none exists; the location check does not prove falsity.
The script restores and byte-checks
sources in `finally`, and finishes with a successful full `lake test`.
Separate streams remain under `.lake/bip39-mutation-checks`.

## SLIP-132 public fixtures

`bip32-public-vectors.json` holds exactly the 12 `ext pub` lines of BIP32 test
vectors 1 and 2, in published order (six each), from
[bitcoin/bips bip-0032.mediawiki](https://github.com/bitcoin/bips/blob/130b8e0fa7f30fa45532f080b87b8db27a79e46e/bip-0032.mediawiki)
at `130b8e0fa7f30fa45532f080b87b8db27a79e46e`, BSD-2-Clause. Its sidecar records
the source digest, authors and extraction; `Bitcoin/LICENSE-bips` preserves
the BIP's notice. No complete document or private column is retained.

`slip132-derived.json` holds 72 independent Python base58 2.1.1 version swaps:
each source, then xpub/ypub/zpub/tpub/upub/vpub. The literal versions come from
cyberkrill `slip132.rs:9-20` at `27cad1faba86260b06665a89f0af5134d23525c2`.
Every result has the expected prefix, checksum and unchanged 74-byte body.
The Lean test compares each conversion to this file in order.

`cyberkrill-slip132.json` holds 48 goldens: each source, then ypub/zpub/upub/vpub,
converted back to xpub or tpub by `parse_slip132_xpub(s)?.to_string()` in a fresh
clone of that revision. Only a temporary pure test is added. Dependencies are
fetched first; the actual test runs offline under `unshare -rn` with a throwaway
HOME. The capture removes its exact workspace, clone and Cargo cache, and
asserts their absence. Each JSON file has its own provenance sidecar.

Regenerate from the root, with `TMP_ROOT` set to a fresh private workspace:

```bash
TMPDIR="${TMP_ROOT:?}" python3 -I packages/bitcoin/generate-slip132-vectors.py
nix shell --impure --expr 'let pkgs = import (builtins.getFlake (toString ./.)).inputs.nixpkgs {}; in pkgs.python3.withPackages (p: [p.base58])' -c python3 -I packages/bitcoin/cross-check-slip132.py
TMPDIR="${TMP_ROOT:?}" systemd-run --user --scope --quiet -p MemoryMax=8G -p MemorySwapMax=0 -p OOMPolicy=continue -p TasksMax=4096 timeout 3600 python3 -I packages/bitcoin/capture-cyberkrill-slip132.py
```

The extract checks 28,032 bytes and SHA-256
`e5e00a8289db2f681052cf24a745320afc225e66b25d1e489a7c884d2fc7f11f`,
and excludes all twelve private strings. The cross-check pins 12/72/48.
The Lean goldens test separately checks every input against an independent
literal-byte derivation, in order. Negative inputs are constructed only at
test time and never printed, including private-version rejections.

`slip132-mutations.json` records four production mutations, the exact detecting
assertion or theorem and the first diagnostic in that theorem's declaration
range. `check-slip132-mutations.py` restores exact bytes in `finally`, keeps
separate streams under `.lake/slip132-mutation-checks`, and finishes with a full
restored `lake test`. Select individual test sets with `lake test -- --slip132 NAME`.

`key-material-mutations.json` now records ten prefixes tested alone against
both the parsed CI command and the Bitcoin test grep: 20 red results plus the
restored scan and missing-path check. Synthetic lines are described, never
stored; their output uses `<synthetic planted line>`. Run from the root after
building BitcoinTests:

```bash
TMPDIR="${TMP_ROOT:?}" systemd-run --user --scope --quiet -p MemoryMax=8G -p MemorySwapMax=0 -p OOMPolicy=continue -p TasksMax=4096 timeout 3600 nix shell --impure --expr 'let pkgs = import (builtins.getFlake (toString ./.)).inputs.nixpkgs {}; in pkgs.python3.withPackages (p: [p.pyyaml])' -c python3 -I packages/bitcoin/check-key-material.py
```

## P2WPKH weight and fee capture

`cyberkrill-fee.json` is captured output on our own synthetic inputs from
[cyberkrill `bitcoin_rpc.rs` at 27cad1faba86260b06665a89f0af5134d23525c2](https://github.com/douglaz/cyberkrill/blob/27cad1faba86260b06665a89f0af5134d23525c2/cyberkrill-core/src/bitcoin_rpc.rs),
MIT OR Apache-2.0, taken under MIT. Its provenance sidecar records the pure
functions called, input order and regeneration command. Integer fields are
decimal strings so u64 values round-trip exactly. There are 18 rate rows,
16 shape rows, 288 shape fees and 144 direct-weight fees, 466 in all.
No upstream source code or private key material is included.

Regenerate from the root with `TMP_ROOT` set to a fresh private directory; the
clone, Cargo cache and build land there. The script only requires `TMPDIR` to be
set and to name an existing directory:

```bash
TMPDIR="${TMP_ROOT:?}" systemd-run --user --scope --quiet -p MemoryMax=8G -p MemorySwapMax=0 -p OOMPolicy=continue -p TasksMax=4096 timeout 3600 python3 -I packages/bitcoin/capture-cyberkrill-fee.py
```

The script checks a fresh clone's pinned HEAD and clean status, fetches locked
dependencies into a private cache, then runs only the upstream `bitcoin_rpc`
test module offline under `unshare -rn`, with temporary HOME and loopback.
It asserts all row counts, order and reference pins before writing the fixture,
and deletes its exact workspace, clone, Cargo cache and HOME in `finally`.
Stdout and stderr remain separate under `.lake/fee-capture-checks`.

## Fee mutation evidence

`fee-mutations.json` records ten changes to the library weight and fee code:
vbytes flooring, missing or unconditional witness flag, witness-element length,
output-script length, each count's CompactSize length, fee flooring, reordered

first failing test assertion and its exit status. `check-fee-mutations.py`
restores exact original bytes in `finally` and finishes with a restored full

package, inside the same capped scope:

```bash
nix develop -c python3 -I check-fee-mutations.py
```

## PSBT proof and definition checks

`psbt-inventory.json` is unchanged. Its 136 transaction occurrences also drive
the `Transaction WellFormed` action: 135 meet the nine library hypotheses, and
`bip174Valid[9]` global record 0 fails only the input/output marker condition.
`measure-psbt-exception.lean` reproduces the witness reader's `truncated` error
on that published zero-input transaction.

`psbt-mutations.json` includes definition-count, decode-half, framing, transaction
hypothesis, inventory-count and measured-error checks. A proof-caught record
now names `theorem_file` and `theorem`; its failure is an actual diagnostic
within that declaration's range in the unmutated file. Runtime-caught records
keep their earlier meaning and format. The proof obligations move fourteen
existing PSBT checks from runtime detection to proof detection; the root README
lists their old assertions, new diagnostics and reasons. `map-noncanonical`
retains its existing proof classification, with explicit theorem metadata.

The runner hashes the proof modules, test modules, mutation targets, inventory,
root modules, lakefile and its own source before accepting `--resume`
checkpoints. It restores the exact original source in `finally`, including when
a handled termination signal unwinds a capped invocation. Checkpoints are
written separately from the script, through an atomic rename. `--discover`
keeps diagnostic logs without certifying or caching a detection.

## PSBT field parity capture

`cyberkrill-psbt-capture.json` records output from
[cyberkrill at 27cad1faba86260b06665a89f0af5134d23525c2](https://github.com/douglaz/cyberkrill/tree/27cad1faba86260b06665a89f0af5134d23525c2),
`onchain-decode-psbt`. Upstream is MIT OR Apache-2.0, taken under MIT;
output only and no source copied.

Inputs are derived from the published BIP174/370/371 vectors at
[bitcoin/bips 927b6de9915c9262615a6399de51b200f81e5aa4](https://github.com/bitcoin/bips/tree/927b6de9915c9262615a6399de51b200f81e5aa4),
BSD-2-Clause, see `Bitcoin/LICENSE-psbt-bips`. Changes: one-record edits derived
by script. Six bases and twelve BIP370 vectors are unchanged (18 rows in all). Base vectors
are selected by published name; every edit asserts exactly one changed or
added record and preserves the other maps and records.

Regenerate from the repository root, with `TMPDIR` set to a private workspace:

```bash
python3 -I packages/bitcoin/capture-cyberkrill-psbt.py
python3 -I packages/bitcoin/capture-cyberkrill-psbt.py --check
```

The script resolves the pinned binary with the caller's HOME before network
isolation. Each invocation reads Base64 on stdin inside `unshare -rn`, with
loopback enabled, a fresh HOME/working directory and a minimal environment.
Its temporary workspace is removed on success and failure. Records retain
separate stdout and stderr and no temporary or binary-store paths. The 49 rows
comprise nineteen must-reject, fourteen must-accept and sixteen port-stricter inputs.
The curve follow-up appends nine one-record edits and the key-only-output base,
and mechanically requires the original 39 rows to remain identical before writing.
Lean tests read these exact Base64 bytes; `--check` independently checks them
against the published bases, edits and a fresh capture. The PSBT mutation
fingerprint includes this record, so changed bytes invalidate checkpoints.
